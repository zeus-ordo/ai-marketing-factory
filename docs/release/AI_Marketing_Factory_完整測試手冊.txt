================================

文件版本：1.0
文件日期：2026-09-06
適用版本：feature/complete-campaign-flow
目前部署版本：4742168
GCP Project：market-factory
GCP VM：ai-marketing-factory / asia-east1-a

重要安全規則
------------
1. 不要把 API key、JWT secret、密碼、cookie、authorization header 或完整 provider response 寫入測試結果。
2. 測試輸出只保留 status、provider、model、attempts、asset count、error code 等安全欄位。
3. 真實 provider 測試必須使用中性 prompt，不可使用客戶機密資料。
4. production 測試前必須先建立並確認 Cloud SQL backup。
5. 測試帳號、測試檔案、測試 campaign 必須使用可識別的 diag/test 前綴。
6. 不可在未確認 company scope 的情況下使用另一家公司資料。


一、測試目標與範圍
==================

本手冊涵蓋：

- Authentication：註冊、登入、登出、email verification、忘記密碼、重設密碼。
- Membership：公司、成員、公司角色、權限、成員角色編輯。
- Permission：Manager Review、Company admin、Platform admin、wildcard、company isolation。
- Review：review queue、diagnostics、approve、reject、revision、audit log、CSV export。
- Folder：Platform folder、Company folder、讀取、使用、建立、編輯、刪除、隔離。
- Campaign：建立、編輯、驗證、啟動、停止、重試、context snapshot。
- Content：knowledge items、references、folder association、reference download。
- Batch upload：多檔案上傳、部分失敗、failed-only retry、移除、campaign start gate。
- Generation：copy、image、video、ads、provider failure、retry、DLQ。
- Operations：health、queue、consumer group、retry、recovery、audit、diagnostics。
- Localization：English、繁體中文、日本語。
- Deployment：backup、Compose、GCP health、image smoke、restart persistence。

測試層級：

L0  靜態檢查：lint、compile、build、diff check。
L1  單元／服務測試：Python pytest、Node contract tests。
L2  離線 E2E：ASGI/TestClient、mock provider、deterministic test files。
L3  Local Compose：真實 containers、local DB、local Redis。
L4  GCP smoke：真實部署服務、中性 provider request、測試帳號操作。


二、角色與測試帳號矩陣
======================

建立或準備以下測試角色。實際 email、密碼與 token 僅放在 password manager 或 secret store，不能寫入本文件。

帳號 A：Platform admin
- 可管理 Platform folders。
- 可讀取所有 company scope 的管理資料。
- 可執行平台維運操作。

帳號 B：Company admin / Company A
- 可管理 Company A 成員與 Company A roles。
- 可建立、編輯、刪除 Company A folders（依授權）。
- 可讀取與使用 Platform folders。
- 不可修改或刪除 Platform folders。
- 不可讀取 Company B 私有資料。

帳號 C：Manager / Company A
- 可進入 Review。
- 可執行被授予的 review actions。
- 可讀取與使用 Platform folders。
- 不可預設取得 member:assign_role。
- 不可修改或刪除 Platform folders。

帳號 D：一般 Company A member
- 只能使用被授權的功能。
- 無 review:manage 時不可進入 Review。
- 不可管理成員角色或 Platform folder。

帳號 E：Company B member/admin
- 用於驗證跨公司 isolation。
- 不可讀取、修改或刪除 Company A 成員、folders、references、knowledge。

測試角色檢查表：
[ ] A Platform admin 建立完成
[ ] B Company A admin 建立完成
[ ] C Company A Manager 建立完成
[ ] D Company A member 建立完成
[ ] E Company B member/admin 建立完成
[ ] 所有帳號均完成 email verification
[ ] 所有帳號 company_id 已確認
[ ] 沒有在測試紀錄中寫出密碼或 token

- 預期：產生 strategy 結果與可追蹤 task。

- 預期：campaign create/run 被拒絕。

ADS-003 Ads failure descendants

- 預期：相關 descendants blocked，無關 tasks 可依 policy 繼續。


十五、Diagnostics、Queue、Recovery 測試

OPS-001 Health
- 檢查 campaign、membership、decision、orchestrator、workers health。
- 預期：JSON status ok 或 HTTP 200。

OPS-002 Queue overview

- 預期：數量與實際任務一致。

OPS-003 Automatic retry

OPS-007 Restart recovery

- 預期：pending messages 被正確 reclaim，已完成任務不重播。

OPS-008 Diagnostics run scope

- 預期：diagnostics 嚴格依 run_id scope。

OPS-009 Audit fields
- 執行 operator action。
- 預期：audit 有 operator/action/result/time，無 credentials。

OPS-010 Alert safety
- 觸發 retry exhaustion、DLQ、persistence error。
- 預期：alert payload 只有 ID 與 sanitized classification。

十七、API 安全與負面測試
=========================

SEC-001 無 token
- 移除 Authorization header 呼叫 protected API。
- 預期：401。

SEC-002 錯誤 token
- 使用無效 JWT。
- 預期：401，不洩漏驗證細節。

SEC-003 Company mismatch
- JWT company_id 與 URL/company 不一致。
- 預期：403 或安全的 404。

SEC-004 Platform mutation
- 一般 company JWT 修改 Platform folder/role。
- 預期：403。

SEC-005 Path traversal
- filename 嘗試 `../secret`、絕對路徑、特殊字元。
- 預期：安全 normalize，不可寫出 upload root。

SEC-006 Oversized body
- 傳送超過限制 body。
- 預期：穩定錯誤，不耗盡記憶體，不留下 partial file。

SEC-007 Error injection
- provider／filename／folder name 放入 URL、HTML、control chars。
- 預期：response、audit、log 經過 sanitize。

SEC-008 Secret scanner
- 執行 secret scanner。
- 預期：新程式碼、test fixture、report 不含 live secret。

18.5 Authenticated batch smoke
------------------------------

使用獨立 QA 帳號執行：

1. 上傳 1 個合法檔案，確認成功。
2. 上傳 2 個合法檔案，確認兩個成功。
3. 上傳 10 個合法檔案，確認 bounded concurrency。
4. 上傳 2 個檔案，其中 1 個故意超過大小限制。
5. 確認 campaign start 被阻止。
6. retry 失敗檔案。
7. 確認只有失敗檔案重傳。
8. 確認成功 reference_id 不變。
9. 確認全部成功後 campaign start 可用。

3. 重新列出資料。
4. 下載 reference/image bytes。
5. 比較 restart 前後 metadata、size、content type、bytes。

預期：資料一致且可讀。

二十、缺陷分級
==============

P0：資料外洩、跨公司讀取、production 全面不可用、資料損毀。
P1：核心流程不能完成、圖片生成假成功、batch failure 仍可啟動 campaign、權限繞過。
P2：非核心功能錯誤、可 workaround 的 UI/API 問題、部分語系錯誤。
P3：文字、排版、低風險 warning、非阻擋改善。

Release blocker：
- P0 或 P1 未修復。
- image empty result 被標記成功。
- batch failed file 仍可啟動 campaign。
- cross-company isolation 失敗。
- secret 出現在 log、trace、DB 或 response。
- backup 失敗或無法確認。
- migration 後 persistence/readability 未驗證。
