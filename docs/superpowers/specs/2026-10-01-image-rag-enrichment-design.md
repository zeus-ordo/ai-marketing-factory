# Image RAG Enrichment Design

## Goal

Upgrade newly uploaded image Knowledge items so they are analyzed
asynchronously into structured RAG attributes and embeddings, while image
generation sends only relevant attributes plus a small number of visual anchor
images.

## Data lifecycle

Existing Knowledge items are not backfilled and remain on the current legacy
path. Only items uploaded after this feature is enabled enter the enrichment
pipeline.

New image upload flow:

```text
upload -> analysis_status=pending -> background job -> processing -> ready
                                                     \-> failed + retryable error
```

The upload API returns success immediately after the file and Knowledge item
are safely persisted. Pending and failed items are not eligible for the new
RAG retrieval path. Existing legacy items continue to be available through the
current matching path for backward compatibility.

## Enrichment data

Add an analysis record associated with each eligible Knowledge item:

- `analysis_status` (`pending`, `processing`, `ready`, `failed`)
- `analysis_version`
- `attributes_json`
- `embedding_status`
- `embedding_model`
- `embedding_dimension`
- `error_code`, `error_detail`
- `attempt_count`, `analyzed_at`, `updated_at`

Structured attributes include OCR text, concise description, objects, colors,
composition, visual style, industry labels, intended use, and safety/quality
flags. Image bytes are read from private storage by the worker and are never
stored in attributes or audit metadata.

## Background processing

Use the existing internal worker/orchestrator seam for an idempotent enrichment
job. The job is keyed by Knowledge item ID and analysis version. It may safely
retry after timeout/provider failure, and a retry endpoint resets a failed item
to `pending` without creating duplicate analysis records.

The analysis provider is configurable. The first implementation must keep the
provider boundary isolated so attributes can be generated by a multimodal
model and embeddings by a configurable embedding provider without coupling
generation requests to ingestion.

## Retrieval and generation

For new enriched items, retrieve structured attributes using metadata filters
and PostgreSQL vector search. Filter by company/platform scope, active status,
industry, Pack role, and `analysis_status=ready` before ranking.

Generation payloads are split by task type:

- copywriting/text tasks receive structured RAG attributes and source
  provenance, without image bytes;
- image tasks receive the attributes plus at most 3 visual anchor images;
- existing mandatory Reference Pack rules and the six-image hard cap remain
  authoritative, with enriched retrieval filling only remaining slots.

Selection audit records candidate count, selected attribute count, selected
anchor count, item IDs, roles, similarity/selection reason, analysis version,
and the visual anchor SHA-256. It never records base64 or storage paths.

## API and UI

Knowledge item responses expose safe analysis fields:

- status
- attributes summary
- retry availability
- analyzed timestamp

Content Studio shows pending, ready, and failed states, supports retry for
failed analysis, and allows inspecting attributes without exposing private
paths. Existing upload, preview, and delete permissions remain unchanged.

## Compatibility and failure handling

- Upload success is independent of analysis success.
- Pending/failed new items are excluded from new RAG retrieval and clearly
  shown in the UI.
- Analysis failures are retryable and auditable.
- If vector search is unavailable, fall back to deterministic metadata matching
  among ready items; do not block uploads.
- Legacy items without an analysis record remain readable and usable by the
  legacy path, but are not reported as enriched.
- All API responses and Context Viewer output recursively remove binary data
  and private storage paths.

## Testing

- Upload returns pending without waiting for analysis.
- Background job transitions pending -> processing -> ready and failed paths.
- Retry is idempotent and versioned.
- Attributes and embedding metadata are stored without bytes or paths.
- Retrieval filters out pending/failed items and respects scope/industry.
- Text payloads contain attributes without image parts; image payloads contain
  no more than three visual anchors plus mandatory Pack images.
- Audit and Context Viewer contain provenance but no binary/path data.
- Existing legacy item behavior remains covered.
