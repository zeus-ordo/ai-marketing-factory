======================================================================
二、第一次測試：上傳圖片並確認 RAG 分析
======================================================================

步驟：

1. 登入前台。
2. 進入 Content Studio。
3. 找到 Knowledge 或 Reference Pack 上傳區域。
4. 上傳一張圖片。
5. 為圖片輸入清楚的標題與描述。
6. 等待分析狀態完成。

分析狀態說明：

- Pending：已成功上傳，等待背景分析。
- Processing：系統正在分析圖片。
- Ready：圖片已可被新的 RAG 流程使用。
- Failed：分析失敗，可按 Retry 重新分析。

Ready 之後，查看 attributes 是否合理，例如：

- 圖片主要物件是否正確
- 色彩是否符合圖片
- 視覺風格是否合理
- 構圖是否正確
- OCR 文字是否正確
- 產業與用途標籤是否合理

如果 attributes 不準確，先檢查圖片是否清楚，再補充標題與描述後重新上傳測試。

======================================================================
三、建立第一個 RAG 測試活動
======================================================================

請先使用一個容易辨識的測試名稱，例如：

RAG-Test-Brand-Green-01

輸入活動資料時，清楚描述：

- 品牌名稱
- 產品名稱
- 產品特色
- 目標客群
- 活動目的
- 品牌語氣
- 希望使用的顏色與風格
- 不可以出現的元素

推薦測試 brief：

「請為我們的品牌建立一組溫暖、自然、高級感的社群廣告。主要使用深綠、米白與木質色調，畫面要保留產品本身的真實外觀，不要使用霓虹色、卡通風格或過度華麗的背景。」

請至少建立兩種任務：

1. 文案生成
2. 圖片生成

======================================================================
四、文案 RAG 測試
======================================================================

文案任務的重點是確認 AI 是否讀懂 attributes，而不是只複製圖片內容。

測試方式：

1. 建立第一版文案。
2. 記錄標題、主要賣點、品牌語氣與禁用元素。
3. 檢查文案是否符合上傳圖片整理出的品牌特徵。
4. 再建立第二版文案，改變目標客群或活動目的。
5. 比較兩版文案是否有正確調整，而不是完全重複。

文案測試檢查表：

[ ] 使用了品牌指定語氣
[ ] 使用了正確的產品賣點
[ ] 沒有捏造圖片中不存在的功能
[ ] 沒有使用禁用詞或禁用風格
[ ] 產品名稱與品牌名稱正確
[ ] 不同目標客群有不同說法
[ ] 文案沒有暴露圖片路徑或系統內部資訊

Context Viewer 中，文案任務理想上應看到：

- 使用了 RAG attributes
- 沒有附加圖片 bytes
- 顯示來源圖片或 Knowledge item 的來源資訊

======================================================================
五、圖片生成 RAG 測試
======================================================================

圖片任務會使用 attributes 加上少量 visual anchor 圖片。

建議依序測試三種情境：

A. 只有品牌識別圖
B. 品牌識別圖加產品圖
C. 品牌識別圖、產品圖加風格圖

每次只改變參考圖片，其他 brief 盡量保持不變。

比較以下項目：

- 品牌色是否一致
- Logo 或品牌識別是否較接近
- 產品外觀是否正確
- 構圖是否接近品牌風格
- 產品是否被錯誤變形
- 背景與整體氛圍是否符合描述
- 是否出現禁用元素

圖片測試檢查表：

[ ] 品牌色一致
[ ] 產品外觀沒有明顯變形
[ ] 產品位置與比例合理
[ ] 視覺風格符合品牌
[ ] 沒有多餘 Logo 或錯誤文字
[ ] 沒有卡通、霓虹色等禁用元素
[ ] 同一組品牌圖片生成結果風格相近

Context Viewer 中，圖片任務理想上應看到：

- RAG attributes
- 少量 visual anchor
- selected image 數量不超過 3 張 enriched anchor
- 全部送給圖片模型的圖片不超過 6 張
- 每張圖片有來源與選取原因

======================================================================
六、如何找到最好的使用解方
======================================================================

不要一次上傳大量相似圖片。建議採用「少量、高品質、角色清楚」的資料組合。

推薦的最佳起始組合：

1. 1 張品牌識別圖
2. 1～2 張清楚產品圖
3. 1～2 張代表性風格圖
4. 1 張實際廣告或社群範例

如果結果不理想，按照以下順序改善：

第一步：改善圖片品質
- 使用清楚、主體明確的圖片
- 避免過度模糊或文字太小
- 避免同一張圖片重複上傳

第二步：改善圖片標題與描述
- 不要只寫「圖片 1」
- 改成「深綠米白品牌產品情境圖」
- 說明這張圖代表品牌、產品、風格或構圖中的哪一種資訊

第三步：拆分參考圖片角色
- Logo 圖只負責品牌識別
- 產品圖只負責產品外觀
- 風格圖只負責色彩、氛圍與構圖

第四步：縮小測試範圍
- 先只用 1 張品牌圖加 1 張產品圖
- 確認結果後，再加入風格圖
- 一次只改一個變數

第五步：改善 brief
- 明確說明一定要保留的元素
- 明確說明禁止的元素
- 說明圖片用途與目標客群

======================================================================
七、建議的 A/B 測試方法
======================================================================

每一組測試只改變一個條件。

測試 A：不使用新上傳圖片
測試 B：只使用品牌識別圖
測試 C：使用品牌識別圖加產品圖
測試 D：使用品牌識別圖、產品圖加風格圖

每組至少生成 2～3 個結果，並以 1～5 分評分：

- 品牌一致性：____ / 5
- 產品準確度：____ / 5
- 色彩一致性：____ / 5
- 構圖符合度：____ / 5
- 文案符合度：____ / 5
- 可直接使用程度：____ / 5

總分：____ / 30

推薦保留總分最高、且最容易重複產生穩定結果的參考圖片組合。

======================================================================
八、常見問題
======================================================================

問題：圖片一直顯示 Pending。
處理：等待數十秒後重新整理。如果長時間沒有變化，記錄圖片名稱與上傳時間，通知管理員。

問題：圖片顯示 Failed。
處理：確認圖片格式與大小，按 Retry。若仍失敗，改用清楚的 PNG/JPG 圖片重新上傳。

問題：AI 沒有使用我的圖片風格。
處理：確認圖片狀態是 Ready，並檢查 Context Viewer 是否列出該圖片。重新測試時只保留 1～3 張最相關圖片。

問題：AI 把產品外觀生成錯了。
處理：增加清楚的產品正面圖，並在 brief 中明確寫「保留產品原始外觀、比例與包裝」。

問題：結果太混亂，顏色和風格不一致。
處理：減少參考圖片數量，移除互相衝突的風格圖，保留一組一致的品牌色與構圖圖片。

問題：文案內容正確，但沒有圖片風格。
處理：這通常是正常現象。文案任務主要使用 RAG attributes；圖片風格應在圖片生成任務中驗證。

問題：同一品牌每次生成結果差異很大。
處理：固定品牌識別圖與產品圖，降低每次更換的參考圖片數量，並使用相同的品牌規則描述。

======================================================================
十、測試完成標準
======================================================================

本次 RAG 測試可視為完成，當下列條件全部符合：

[ ] 至少 3 張圖片成功分析為 Ready
[ ] 至少完成 1 次文案生成
[ ] 至少完成 1 次圖片生成
[ ] Context Viewer 能看到參考資料來源
[ ] 文案結果符合品牌語氣與產品資訊
[ ] 圖片結果符合品牌色、產品外觀與視覺風格
[ ] 沒有 private path、base64 或系統內部資料出現在畫面
[ ] 已記錄最佳圖片組合與改善建議

測試完成後，請將測試紀錄與 2～3 個最佳生成結果交給專案負責人，作為下一輪 RAG 優化依據。
